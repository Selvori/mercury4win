- 去重同时使用地址身份与保守的站点/名称/文章链接证据，不以同名直接合并不同源。已有有效订阅及相关资料保留，历史重复源不自动合并或删除；旧版从未成功且无文章的失败占位在重新导入时恢复或条件清理。
- 细则与验收边界：[测试入口](../tests/feed_import/README.md)、[原生报告](audits/feed-import-2026-10-29.md)。

## D-016：多语言关键词先展示，AI继续核验

- 日期：2026-10-28；状态：已接受。来源：用户要求大模型扩展多语言关键词，部分命中即先展示，减少等待，再逐步进行AI检索。
- 决策：复用一次主题理解请求生成多语言词，扁平OR匹配硬条件内最新100篇本地标题/摘要/正文；按命中词及字段权重排序，短ASCII词按词边界匹配。默认不查笔记，显式笔记字段才参与。初步结果可阅读、排序、分页及批量处理，清楚标为尚未AI核验。
- 决策：同一次提交继续标题/预览/连续正文/最终依据核验，逐步添加或移除结果；AI确认成员排在初步成员前。列表显示可见数、AI确认数与待核验数，空快照也更新。错误/暂停保留当前快照，可显式恢复；收起面板继续工作，同一查询更新保留当前阅读文章，取消恢复此前范围。
- 决策：成员变化发布不可变令牌，既有分页/批量版本检查保持。Schema10沿用；算法改topic-search-quick100-v4，旧算法检查点不再提供恢复，旧结果仍可读。关键词快照不代表AI相关性或完整正文核验。
- 影响：补充D-015最新100篇约定，替代关键词仅作内部优先级的限制；内容依据、默认不发笔记及不自动补抓约定保留。[实现与验证](audits/staged-search-quick-2026-10-28.md)。

## D-015：默认仅搜索符合条件的最新100篇

- 日期：2026-10-28；状态：已接受。来源：用户明确要求默认按最新100篇搜索，不必筛选所有文章。
- 决策：先应用来源、标签、日期等硬条件，再按与普通最新排序一致的发布时间降序/ID降序固定最多100篇，无发布时间排后；不足100篇取全部。语义词只在这100篇内提供优先级，不能把更老的相关文章拉入。用户切换结果排序不改变本次成员。
- 决策：100篇内继续标题/预览/完整可用资料分块及最终原文依据核验，可暂停恢复；普通关键词搜索不加100篇总范围限制。界面明确较旧文章不参与本次AI搜索。
- 决策：算法身份改为topic-search-latest100-v3，旧全量工作不再提供恢复入口，不截断或删除旧检查点/结果；旧不可变结果令牌仍可读取。新查询按新范围创建，缓存身份独立，不改Schema10。
- 影响：替代D-014的全硬范围标题池约定，其内容核验、取消、快照、来源版本与无自动补抓/默认不发笔记约定继续保留。验证见[最新100篇报告](audits/staged-search-latest100-2026-10-28.md)。

## D-014：全标题初筛、完整资料分块与可恢复的有限扫描

- 日期：2026-10-28；状态：已接受。来源：用户确认分阶段检索方案并要求继续实现、真实模型与隔离桌面验收。
- 决策：先解析主题和可表达的硬条件，固定本次允许范围，遍历其中全部标题。中英关键词只提供排序和后部段落救援，不是标题池的准入条件；“新”不自动变成最近七天。模糊、空白、合集及多主题标题保留；标题相关仅代表入围，分数不是概率。
- 决策：入围预览同时含摘要、正文开头、章节标题和本地相关段落。信息不足继续读取完整可用资料；全文按连续字符范围分块，带文章上下文、反证及历史引用信息，全部块提交后才做整篇判断。缺正文不自动抓取，可按标题/摘要形成明确标记的结果；笔记只在显式选中笔记字段时发送。
- 决策：一次提交自动处理这个有限范围，取消36篇及手动逐批继续边界。阶段、块及已确认结果持久化，用户可暂停、取消、恢复或重启后载入；后端取消实际任务，旧请求不得晚提交。不建后台常驻扫描、不设置固定总token预算、不无限重试；按实际资料长度组不同阶段批次。
- 决策：算法、主题、配置、硬条件及资料版本绑定缓存，仅处理新/变资料。结果逐步发布为新的不可变服务端令牌；分页、排序和批量操作使用点击时的确切令牌，不因后续扫描扩大。新增文章留待下次；变更或删除的来源明确过期，严格批量操作拒绝过期资料。
- 2026-10-28 容错补充：标题仅是初筛优化。正常HTTP后的标题判断无法校验时，丢弃整批模型判断，将原始已冻结ID保留到内容检查，单独显示数量；不自动重试、不接受其未知ID/排除结论、不缓存失败判断。预览/正文与最终相关依据的校验继续独立执行。
- 影响：Schema 10；当前算法 `topic-search-staged-v2`。D-013 的词法准入、36篇及显式逐批继续约定由本项替代，其普通搜索、隐私、独立范围和暂禁保存 AI 智能视图的约定保留。实现与复验入口见[分阶段检索测试](../tests/staged_search/README.md)。首次完整扫描可能比旧36篇消耗更多；覆盖全部标题不保证没有语义漏检。

- 日期：2026-10-28；状态：部分约定由 D-014 替代，原阶段记录保留。来源：用户要求跨语言语义召回、内容判定、实际模型评估和隔离桌面验收，撤销此前仅生成本地词法条件的限制。

- 决策：明确提交才付费，一次最多 36 候选，显示候选覆盖与剩余数量，显式继续；失败 / 取消保留旧有效列表。独立且不可变的服务端结果范围支持分页 / 批量，不在普通筛选中塞全部成员 ID。当前 AI 范围不保存为智能视图，原条件视图继续可用。

- 影响：Schema 9 与 topic-search-v4；老解析 IPC、普通搜索、专题以及历史兼容标识保留。实际验证与边界见 [主题搜索测试说明](../tests/topic_search/README.md)。

## D-009：以成功资料快照为基线的主题追踪

- 日期：2026-10-26；状态：已接受。来源：用户明确要求完整实现主题追踪与增量简报，并优先新功能。
- 决策：专题由用户确认成员；智能视图只提供规则副本形式的候选范围，原视图变动不静默改变专题。相同正文自动归组，允许人工纠正，近似转载仍需核对；不自动全库聚类、抓取或调用 AI。
- 决策：Schema 7 分开保存专题、成员、运行和简报版本；用户判断独立存储。成功版本冻结正文、来源、归组、模型和引用位置；增量基于上个成功版本，而非时间筛选或旧摘要拼接。无变化不请求，失败／取消不推进基线，提交时核对资料及专题身份并使用既有取消围栏。
- 决策：使用独立 topic 任务／用量类型，复用摘要任务的主／备用模型路由；不污染单篇结果。来源和模型输出视为不可信文本，结构／原文片段校验只确认引用位置，不能证明主张成立；旧引用保留冻结正文，不能重新跳到错误段落。
- 理由：让持续订阅形成可核对、可纠正、可重开的主题研究记录，同时保留无 AI 的资料管理能力。当前范围、上下文限制、实现与验证边界见[专项报告](audits/topics-2026-10-26.md)。

- 2026-10-26 补充：默认手动确认与研究对照的产品路线由 D-010 替代；成功快照、独立备注、引用和旧手动模式继续保留。

## D-010：一句话主题、自动选文和信息简报

- 日期：2026-10-26；状态：已接受。来源：用户明确要求简化操作，选择主题后由 AI 自动选取相关文章并生成简报，更新时一键生成；主旨是获取信息。
- 决策：新主题默认自动整理，一句话即可创建并开始；来源、关键词、日期和预算为可选高级设置。关注问题、证据裁决、真假评分和逐篇审批不作为必经流程。旧专题保留手动模式，只有用户显式切换才启用自动发现，不改写旧成员、规则或历史。
- 决策：有界本地发现之后，必须实际调用 AI 判断相关性、重复报道和新增信息，再自动生成“本期要点 / 展开了解 / 值得一读”。本地匹配只能叫候选。反馈、引用、快照、历史、独立备注和 Markdown 导出作为底层支撑及可选操作。
- 决策：已检查资料版本、成功简报基线和已读位置分开保存；无新信息可记录检查结果，但不制造成功简报或推进已读。失败 / 取消保留待处理内容；无候选变化不请求 AI。默认只在显式生成时调用，不在同步后付费，不建立定时任务或后台全库处理。
- 决策：只覆盖已有订阅的本地资料；明确发现窗口、预览、完整正文与缺全文依据，超预算显式延后或拒绝。受控 Provider 的流程通过不能代表真实模型质量，引用位置存在不能证明表述正确。
- 理由：减少操作，让持续订阅直接变成可阅读的新信息，同时保留纠错、追溯、失败恢复和无 AI 能力。[本轮实现与验证边界](audits/topics-auto-2026-10-26.md)。

## D-011：简报以连续文章阅读，来源集中在文末

- 日期：2026-10-27；状态：已接受。来源：用户明确要求不要一个个小卡片，而是可连贯阅读的一篇文章；证据放在文末，不必显示 AI 模型名称。
- 决策：正文使用连续散文段落，不展示内部 kind 栏目标签或逐段引用按钮；来源及可核验的原文片段集中于文末，相同片段去重。生成提示要求开篇、展开和自然收束，并用过渡连接各段。旧简报不自动调用 AI 改写，直接沿用新排版。
- 决策：阅读界面和 Markdown 导出不展示生成模型 / Provider 名称；模型身份仍留在内部历史与用量中，与新闻内容相关的产品或模型名称不删改。导出正文先完整呈现，随后列来源、原文片段、版本及独立备注。
- 影响：沿用原 claims / citations / 冻结快照契约和 Schema；自动写作 Prompt 为 topic-article-v3，旧手动模式写作 Prompt 为 topic-comparison-v2。来源校验、历史、个人备注和反馈仍可使用，不能为排版变化重置成功基线或付费重写历史。

## D-012：移除简报的应用内 token 预算

- 日期：2026-10-27；状态：已接受。来源：用户明确要求删除 token 预算限制。
- 决策：删除专题高级设置的预算输入与范围校验，自动选文不因 UTF-8 字节估算缩小批次或要求模型因长度放弃文章；所选全文不按预算延后。自动 / 手动简报请求都省略固定 max_tokens，手动模式同时移除正文与上下文总字符预算。实际服务端上下文 / 输出能力及错误由其返回，失败继续保留可重试状态。
- 决策：发现窗口、每批候选 / 选中数量及输出结构 / 原文定位校验属于资料范围与正确性约定，保留现有行为，不改成全库抓取或后台 AI。旧 input_budget 列、返回字段和旧保存参数仅为兼容保留；生产保存忽略该参数，不影响请求。缓存沿用旧身份格式以复用同批有效选文，不通过删除预算清空既有状态。
- 影响：无迁移 / 依赖升级或历史数据重写。D-010 的可选预算及此前超预算延后约定由本决策替代；D-011 的文章式输出保留，自动写作 Prompt 现为 topic-article-v4，并强化多段落引用使用独立对象。
