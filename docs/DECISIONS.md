## D-004：请求事实与结果提交独立，Provider /Model 归档保留身份

- 日期：2026-10-13；状态：已接受。来源：用户授权按串行方案修复M4W-012、上游token-usage逐请求 /软删除约定及本轮已确认实施方案。
- 决策：新用量以每次实际HTTP尝试为事实，成功 /失败 /取消 /超时均保留；未知Token为NULL。HTTP结束与业务结果COMMIT分属不同生命周期，日志不采用结果取消fence。旧聚合不可重建的请求数 /0值可用性不伪造，作为legacy保留并独立报告；本地报表UTC区间和日桶明确。
- 决策：Provider /Model退出活跃配置使用事务归档而非硬删除，不移除凭据或历史 /profile引用。Provider创建规范endpoint+同名称可恢复原ID /原Key（界面明示）；不同名称新身份防隐式继承旧账户。Provider恢复不自动恢复模型，Model按同Provider+model_name恢复；显式能力参数生效，旧调用恢复保留原能力。
- 理由：真实请求数 /Token和历史身份不能因任务失败、取消、合并统计或配置删除而丢失；有限独立DB写避免持久化与取消调度互相锁住。归档和保留历史不代表新的任务可用，实际route必须排除归档 /禁用对象。
- 影响：schema v5兼容旧行；后续迁移继续保留可追溯性。正常日志等待写完成，取消仅有限DB写；写失败可观测，但强杀进程未完成日志不保证。凭据仍为原XOR混淆格式，本决策不宣称安全加密。实现 /隔离证据见[012回归](../tests/usage_lifecycle/README.md)，桌面验收仍待完成。

## D-005：Obsidian Publish 采用静态专用阅读分支

- 日期：2026-10-13；状态：已接受。来源：用户授权串行修复M4W-013、上游obsidian-pub明确v1范围及本轮确认方案。
- 决策：以高可信shell的静态siteInfo /preload URL解析接管阅读；不执行网页脚本 /WebView hydration。pipeline_type与resolved_intermediate_content记录分支及Markdown URL，cleaned_html /Readability元数据继续属于default，canonical Markdown与最终安全渲染共享。
- 决策：成功解析后失败保留pending身份、没有成功正文 /缓存，继续本分支重试。媒体只按公开资源索引唯一匹配，歧义 /索引失败保留原文本。未支持的动态声明和Obsidian专用语法保持明确范围，不采用路径猜测。
- 理由：shell的正文缺失属于来源解析问题；不得把重复Readability shell、未知媒体或网络失败记录为成功文章。消费者应按实际管道判断canonical Markdown有效性。
- 影响：无schema /权限变更；Readability版本3使旧default shell重新解析。具体受限host /uid /重定向 /缓存契约与未验证范围见[013回归](../tests/obsidian_publish/README.md)。

## D-006：选择翻译即开始，阅读区仅展示对照正文

- 日期：2026-10-13；状态：已接受。来源：用户明确要求隐藏翻译操作 / 进度等信息、按钮或T直接翻译并修复漏译。
- 决策：进入翻译模式先解析实际配置与来源 / 缓存 / 后台状态，完整结果直接展示，没有完整结果时开始或继续缺段；每次激活最多一次，失败无隐式重试循环。再次切回原文、重新选择翻译可显式重试；切文章默认原文。应用阅读区不显示额外翻译侧栏或控制 / 状态面板。
- 决策：翻译覆盖正文标题、引用、表格文字等可见自然语言块，代码块及非正文区域原样；修改来源映射时升级分段身份以防旧“完整”缓存继续漏译，保留旧记录。译文按textContent插入合法HTML位置，不扩大iframe权限。
- 理由：翻译交互直接服务对照阅读；先恢复缓存及等待真实配置避免冗余请求，来源范围应覆盖阅读正文而不受上游旧p / ul / ol范围限制。
- 影响：当前分段版本reader-html-block-v3，无数据库迁移。实现及隔离证据见[翻译回归](../tests/translation/README.md#2026-10-13-静默直接翻译与漏译范围)，native桌面与真实Provider验证仍待完成。

- 决策：无有效界面偏好时默认 zh-Hans，提供中英选择并以新增 mercury_locale 保存；不依据英文系统语言覆盖用户的中文选择。界面语言同步根 HTML、日期 / 数字格式和文摘的应用生成标题，不改写文章原文，也不覆盖已有 AI 任务的目标语言。

- 理由：现有中文资源需要实际生效，重启必须保留选择；界面语言、AI 输出语言和来源内容各有用途，避免中文化引发付费任务配置或已有内容变化。
- 影响：不改历史 localStorage 键、数据库 / 凭据 / 应用标识、Schema 或依赖。实际隔离验证见 [中文化入口](../tests/localization/README.md)，native 完整退出重启及系统窗口尚待验收。

## D-008：本地全文搜索与动态智能视图

- 日期：2026-10-26；状态：已接受。来源：用户明确要求本轮完整实现全文搜索与智能视图，优先新功能，不以前序旧 native 验收为开发前置。
- 决策：本轮采用词法匹配，覆盖本地标题、Feed 摘要、已有正文和已保存笔记，不自动全库抓取或调用 AI。空白分词后 AND，字符 / 符号按字面匹配；FTS5 trigram 处理三字以上词，短词另走字面路径，不能假设 trigram 已解决中文双字。
- 决策：Schema 6 添加可丢弃重建的索引、持久更新队列和智能视图；来源数据为权威。启动迁移不解析全库，首次搜索在工作线程分批建立索引；源变更排队，搜索前刷新。高亮返回文本片段与标志，由 React 安全渲染。
- 决策：视图保存关键词、来源 / 标签 Any/All、日期 / 相对天数、阅读 / 收藏 / 笔记条件及排序。相对 N 天保存规则，分页使用同一时间锚点，应用写入与定时重查更新活动视图。删除视图保留文章；缺失来源或标签不静默放宽条件。
- 决策：查询与全范围已读共享参数化条件编译器；批量已读包含未加载页，文摘保持已加载文章的手动选择快照与顺序。默认最新在前，支持按字段权重相关性及最早在前，并以时间 / ID 稳定分页。
- 理由：让已有阅读资料可找回，兼顾中文短词与代码词，不引入向量库、付费检索或网络依赖。实现、性能实测、失败与平台边界见[专项报告](audits/search-views-2026-10-26.md)。

## D-009：以成功资料快照为基线的主题追踪

- 日期：2026-10-26；状态：已接受。来源：用户明确要求完整实现主题追踪与增量简报，并优先新功能。
- 决策：专题由用户确认成员；智能视图只提供规则副本形式的候选范围，原视图变动不静默改变专题。相同正文自动归组，允许人工纠正，近似转载仍需核对；不自动全库聚类、抓取或调用 AI。
- 决策：Schema 7 分开保存专题、成员、运行和简报版本；用户判断独立存储。成功版本冻结正文、来源、归组、模型和引用位置；增量基于上个成功版本，而非时间筛选或旧摘要拼接。无变化不请求，失败／取消不推进基线，提交时核对资料及专题身份并使用既有取消围栏。
- 决策：使用独立 topic 任务／用量类型，复用摘要任务的主／备用模型路由；不污染单篇结果。来源和模型输出视为不可信文本，结构／原文片段校验只确认引用位置，不能证明主张成立；旧引用保留冻结正文，不能重新跳到错误段落。
- 理由：让持续订阅形成可核对、可纠正、可重开的主题研究记录，同时保留无 AI 的资料管理能力。当前范围、上下文限制、实现与验证边界见[专项报告](audits/topics-2026-10-26.md)。
