## 正文来源与失败回退

临时 loopback 服务 `127.0.0.1:18745` 提供合成 RSS 与文章；通过原生 OPML 导入，4 篇文章由生产解析器与实际同步入库。

- 显式短 `content:encoded` 在 Reader 显示“显式 Feed 正文”和 `NATIVE005_EXPLICIT_FULL 保留原文，短正文。`，与 Feed 原文一致；服务日志没有 `/article/full` 请求。完全停服务后再次选择仍正常阅读。
- 只有 description 的 teaser 实际请求 `/article/teaser`，HTTP 200 / 3207 bytes，Reader 显示 `NATIVE005_TEASER_FETCHED_FULL` 和完整段落；SQLite 原 HTML / Markdown / 阅读缓存存在。
- `/article/failure` HTTP 503 后，Reader 显示中文导读、“可能不完整”来源提示和“重试获取全文”；`content` 无行、成功 HTML 缓存为 0。
- `/article/offline` 连接中断后相同临时导读；完全停止服务、18745 无监听后点击重试，导读和来源提示保持，无成功缓存。

## 验收中发现的问题

原生导入本机空响应源：HTTP 200 / 0 bytes，进度却显示绿色成功、已添加 2（另一个正常源）。根因是 `import_opml_stream` 将 `Ok(SyncResult { error: Some(...) })` 当成功；普通 `import_opml` 同样遗漏该错误。已最小共享结果归一函数，保留订阅添加事实，同时将嵌套同步错误传入原有错误通道；无 IPC 模型变化。后续验证结果另记，不能以静态修复当验收通过。
