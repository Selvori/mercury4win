## 交付行为

- 新主题默认自动模式；输入一句话即可“创建并生成简报”，也可“仅创建”。来源、日期、关键词等可选范围沿用智能视图的规则副本，说明、模式和输入预算放入高级设置；默认不要求事先建视图。列表卡片显示候选更新、上次成功时间和未读状态，可直接生成或阅读。
- 本地候选与 AI 选文是两个步骤。默认发现窗口为最近入库的 1,000 篇，附加显式保留资料；使用现有搜索条件编译器限定可选规则。局部词法提示与少量中英别名优先排序，并保留近期发现通道，不把本地命中称为确定相关。AI 实际接收候选 ID、元数据与预览，判断相关性、同名歧义、重复报道和新增信息，再自动进入总结。不是将本地关键词匹配改名为 AI。
- 每次最多 60 篇预览、AI 最多选 12 篇；本地排序的两个通道可能重叠，因此实际批量可少于 60。预览最多 1,000 字符，携带完整性和正文大小标识。输入预算不足时缩小批量，界面提示本批与待处理范围；未发送的候选不标为已检查。
- 简报默认使用“本期要点 / 展开了解 / 值得一读”，介绍事件、重要细节与原文。仅实际影响理解的分歧才需要说明。来源、运行记录、手动资料补充与历史渐进展开；个人判断仍独立保存，旧手动对照简报保持兼容。
- “本次采用的文章”支持打开正确的当前文章、“与主题无关”、排除此文及恢复候选资格。反馈按主题 / 文章持久化，不删除文章，也不改写历史快照。显式重新加入资料会恢复该文章的候选资格；没有训练跨文章偏好模型。
- 没有正文时，自动模式仅可使用冻结的标题与 Feed 摘要，界面、请求、简报项目及导出注明依据范围，不能伪装成全文。主动抓取按钮继续复用原正文管道；本轮不会静默抓取全库或在同步后自动调用 AI。
- 同一摘要兼容模型路由用于选文和总结，只有一个可用模型也能工作。复用独立 topic 运行时、Channel、取消围栏、Provider 身份和逐请求用量。筛选和总结都产生真实 HTTP 请求记录，失败 / 取消 / 备用请求沿用现有规则；不伪造未知 token，不承诺费用降低。

## 数据、恢复与边界

Schema 8 后续迁移新增自动 / 手动模式、已读简报 ID、资料检查时间、输入预算，以及已检查版本、文章反馈和筛选缓存表。旧专题仍为手动模式，只有显式修改设置才切换；旧成员、规则、备注、简报 JSON 和原文引用保持。Source 新依据字段对旧 JSON 默认兼容，并从旧手动哈希的序列化中省略空字段，避免升级制造假增量。

资料检查位置、成功简报基线和已读位置分开保存：

- 使用范围身份及文章内容版本，不使用发布时间水位作为处理游标；迟到的入库文章、窗口内旧文修订、正文就绪和搜索规则变化能够重新进入候选。发现窗口之外、且未显式保留的旧文章不在本轮保证范围内。
- 有候选但 AI 判断无值得补充的信息时，事务保存 `no_information` 与已检查版本，成功简报和已读位置保持。无候选变化时，命令在读取模型凭据前返回，不请求 AI。
- 筛选缓存由候选 ID / 版本、主题修订、成功基线、配置身份、语言和预算共同标识。总结失败可复用有效筛选；失败或取消不确认候选，不推进成功基线。相同请求的已成功简报可返回原 ID，提交仍检查并发基线和取消围栏。
- 总结携带上个成功结果、历史信息概览，以及所选修订文章在整个成功历史中最近使用的原文快照。没有把所有历史正文塞入每次请求；请求明确说明旧正文覆盖范围。原始完整快照仍本地保存，旧引用不会重新绑定到当前正文。
- 默认输入预算为 24,000，以 UTF-8 字节及消息开销作保守估算，并非实测 tokenizer 用量或模型容量；最多请求 4,000 输出 token。用户应按模型实际上下文能力调整。所选完整正文放不下时，可处理仍能容纳的资料，其余明确留待处理；单篇与历史仍超预算时拒绝且保留筛选缓存，不截断全文后声称已读。长期历史概览也受预算限制，未承诺无限历史上下文。
- 输出只接受本批真实文章 ID、合法栏目及唯一原文片段；重复引用去重，非法 ID / 歧义片段 / 缺支持 / 超限输出拒绝。引用仅证明位置存在，不证明语义正确。来源和输出在界面按文本安全显示，不增加桌面权限。
- 已读由用户显式标记，重启后保留；无新信息检查不伪装成新简报。删除主题只删除主题数据。
