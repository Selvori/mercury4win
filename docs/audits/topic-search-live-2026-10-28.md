# AI 主题搜索真实 API 评估

日期：2026-10-28，Windows / PowerShell 7.6.7，基线 81f7b2e 加保留的全部未提交修改。用户明确批准真实 API 与 Computer Use；本报告只讨论真实 HTTP / 模型路径，原生受控交互见独立报告。

只读连接日常库中的 AI 配置白名单，在内存中解码所选主路由凭据。所有业务资料来自固定人工标注的 [20 篇合成语料 / 7 例](../../tests/topic_search/corpus.json)，日常文章 / 正文 / 笔记未读取或发送，日常库未写入。沿用生产理解 → 本地召回 → 逐篇模型判定 → SQLite → 结果分页路径，不以人工响应代替语义质量判断。

每轮主模型最多 28 请求，无 fallback / 自动重试；诊断单例单独记录，不算整套通过。模型均为当前摘要主模型 ecnu-plus。以下均为实际执行结果，失败未覆盖：

这些可恢复记录已确认 **59 请求 / 86,226 token**，最终一轮 15 请求 / 22,100 token 的服务端用量均完整；**另有首轮计量丢失，不能宣称这是全部真实消耗。** 2026-10-27 旧词法阶段的 10 请求 / 7,944 token 是此前独立记录，不混入本表。

实际修正：每种语言独立提供宽泛主体路线；不向模型提供与显式引用无关的元数据，也不发送手动数据库 ID。正文片段从每组首个短词匹配改为各词首尾候选，按具体程度与词密度选取；maintenance 内的 ai 抢占后部 Harbor-11 发布消息在单元回归中先失败、后通过。模型仍负责语义判定，没有硬编码 AI 别名字典代替判定。概念组容纳四组且保留原 AND 语义；完整 JSON 围栏只剥外壳，已知重复硬条件仅在与全局完全一致时归一，额外字段 / 冲突 / 非候选 ID / 改写依据继续拒绝。

最终生产版本为 topic-search-v4，实际结果：中文 / 英文模型发布均为 1–6；陌生型号为 1；数据库性能为 20、21、22；构建工具为 30、31；明确一周 / 收藏 / 来源为 1、5；无相关文章为空。ID、证据逐字校验及候选剩余为零均通过，未跨轮挑选成功案例。随后修正字段专用召回的通道边界，受控回归通过；没有为该局部字段修正再请求真实模型，固定七例的默认字段行为不受影响。小样本不代表稳定命中率、服务 SLA 或全库语义覆盖，当前未做大库 / 其他模型 / 多平台评估。
