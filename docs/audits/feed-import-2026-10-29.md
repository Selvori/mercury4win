# RSS导入：同源去重、一次重试与失败不留订阅

日期：2026-10-29（北京时间）；基线99a6bb7及任务前未提交的RSS诊断/日志。Windows / PowerShell7.6.7 / Rust GNU / Tauri WebView2。用户截图指出小众软件、阮一峰重复，并明确要求失败重试一次、最终失败不留侧栏项。

## 实现

1. 新`feed/import_service.rs`统一普通/流式OPML与手动添加。先抓取并解析，再保存；HTTP、空响应、解析错误及0文章首次失败会发送`retrying`并等待300ms，最多再抓一次。数据库失败不重复抓取。Feed请求使用单请求30秒超时；同步也使用相同有界抓取，AI共用客户端参数保持原样。
2. `feed_store`在写事务内重新检查身份，订阅/首批文章/同步时间一起提交。`entry_store`仅抽出既有upsert事务内部函数，保留原GUID/URL去重和阅读缓存失效逻辑。新订阅失败回滚；旧版从未成功且无任何文章的占位，在本次重试失败后条件清理，成功则复用原ID。已有文章、已读/收藏/笔记/标签/AI数据不删除。Schema保持10。
3. 地址归一保留路径大小写/查询/端口/账户信息；不同地址的别名要求同名、相同站点（兼容旧RSS站点缺省）、至少3个文章URL相同且占较小窗口80%。不以同名或同站单独判重，不自动合并历史已有文章的重复源。此为保守识别，不能保证所有内容不足或改名的别名都能识别。
4. 实测发现RSS不带rel的channel link此前未写入site_url，补上无rel链接回退，保留Atom alternate优先；使用HTTP重定向最终URL解析相对链接，缺失站点时保留OPML提供值。截图对应的四个实际公开响应快照经生产解析/保存只得到2源。
5. 前端按current而非feed_url更新每行，修复同文件重复URL覆盖前一次状态/计数；新增retrying状态及中英说明。IPC签名/注册不变，ImportProgress TypeScript同步新增状态，结果仅成功添加计入added。
